# Financial Sentinel
### Explainable Financial Risk & Decision Intelligence

A end-to-end data science project that detects anomalous financial transactions, scores them by real business risk, forecasts future spending, and explains every decision through an AI analyst grounded in real data.

---

## The Problem

Financial systems generate thousands of transactions daily. Traditional anomaly detection flags everything unusual — creating alert fatigue where analysts review hundreds of low-priority events while genuinely dangerous transactions get buried. 

**Financial Sentinel** solves this by combining statistical analysis, machine learning, and financial impact estimation to surface the transactions that actually matter — and explain why.

## Milestones

### Milestone 1 — Data Science Foundation
- **Synthetic data generation** with realistic lognormal distributions, correlated entity relationships (employees → departments, vendors → categories), and two independent ground-truth labels per anomaly
- **EDA**: amount distributions, spend by department/category/vendor, transaction frequency by hour
- **Feature engineering**: employee-relative and vendor-relative deviation scores, off-hours flag, duplicate detection
- **Statistical baseline**: Z-score + IQR rules — establishes a benchmark to beat
- **Isolation Forest**: outperforms baseline by 22× on precision (0.317 vs 0.014)

**Key design decision:** Two separate labels per anomaly — `anomaly_type` (for detector evaluation) and `true_risk` (for risk ranker evaluation). These are deliberately not the same. A transaction at 3am is statistically anomalous but not automatically risky. A duplicate invoice is always risky. Conflating the two would make risk score evaluation meaningless.

### Milestone 2 — Risk Intelligence
- **Risk engine**: weighted combination of anomaly score, financial impact, behavioural deviation, and contextual signals
- **Alert prioritisation**: ranked by risk score, evaluated with Precision@K and Risk-Capture@K
- **SHAP explanations**: per-transaction feature attribution using TreeExplainer on Isolation Forest

**Results:**

| K | Precision@K | Risk-Capture@K |
|---|---|---|
| 10 | 1.000 | 0.014 |
| 20 | 1.000 | 0.028 |
| 50 | 1.000 | 0.069 |
| 100 | 0.890 | 0.123 |

Top 20 alerts: 100% precision — every alert is a genuine risk.

### Milestone 3 — Predictive Intelligence
- **Three forecasting models**: Moving Average (baseline) → Exponential Smoothing → ARIMA
- **Stationarity testing**: ADF test to determine ARIMA differencing order
- **Evaluation**: MAE, RMSE, MAPE on 3-month holdout

**Results:**

| Model | MAPE |
|---|---|
| Moving Average | 4.64% |
| Exponential Smoothing | **1.61%** |
| ARIMA(1,1,1) | 3.02% |

Exponential Smoothing outperforms ARIMA — expected with only 19 months of data. ARIMA needs ~36+ observations to be competitive.

- **Drift detection**: linear trend fitting per department/category with R², p-value, and % change over observation window

### Milestone 4 — AI + Deployment
- **Tool-calling AI analyst**: Gemini with 8 data tools. The LLM cannot invent financial figures — every claim is traced to a tool result
- **FastAPI backend**: 9 REST endpoints serving all data and the agent
- **Dashboard**: single-file HTML frontend with live risk feed, SHAP bars, forecast table, and AI chat

## Key Technical Decisions

**Why lognormal for amounts?**
Real transaction amounts are right-skewed — most are small, a few are large, none are negative. Normal distributions produce symmetric data with negative values. Using `np.random.lognormal` with department-specific parameters produces realistic distributions where `mean >> median`.

**Why two ground-truth labels?**
`anomaly_type` (statistical rule violated) and `true_risk` (genuinely dangerous) are different questions. Evaluating the risk ranker against anomaly detection labels would produce misleading metrics — a time-of-day anomaly gets perfect recall but zero business value.

**Why Precision@K over F1?**
Analysts review ranked lists, not flat classifications. "How good are the top 20 alerts?" is the real business question. F1 treats all thresholds equally; Precision@K measures performance at the decision boundary analysts actually use.

**Why SHAP on Isolation Forest?**
Financial systems require explainability — "risk = 93" is not actionable without "because vendor deviation = +505%, frequency = 11 vs. avg 3". TreeExplainer on IF returns feature contributions in anomaly-score units (not probabilities), which is a known limitation acknowledged in the codebase.

## Setup & Running

### 1. Clone the repo
```bash
git clone https://github.com/YOUR_USERNAME/financial-sentinel.git
cd financial-sentinel
```

### 2. Install dependencies
```bash
pip install numpy pandas scikit-learn shap matplotlib seaborn statsmodels joblib fastapi uvicorn google-genai
```

### 3. Generate data and run all milestones
```bash
python data/generator/generate_data.py
python src/milestone1.py
python src/milestone2.py
python src/milestone3.py
```

### 4. Start the API server
```bash
python -m uvicorn api.main:app --reload --port 8000
```

### 5. Open the dashboard
Open `frontend/dashboard.html` in your browser.

### 6. Use the AI analyst
Get a Gemini API key from [aistudio.google.com](https://aistudio.google.com), paste it in the dashboard header, and ask questions in plain English.
